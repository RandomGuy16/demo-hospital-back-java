# AI Triage & Smart Scheduling: Implementation Roadmap

This document outlines the architectural requirements, domain changes, and step-by-step implementation plan for building the **AI Triage & Smart Scheduling System** in Evergreen General Hospital.

---

## 1. Overview & Architecture

The AI Triage system enables patients to describe their symptoms in natural language, automatically classifies clinical urgency, suggests the appropriate medical department/specialty, identifies matching practitioners, and facilitates frictionless one-click booking.

```
                                  +-----------------------------+
                                  |     Patient / Client UI     |
                                  |  (Next.js App / Conversational)
                                  +--------------+--------------+
                                                 |
                                                 v
                       +-------------------------------------------------+
                       |            AI Triage Engine (LangChain)         |
                       |  - Analyzes symptoms & chief complaints         |
                       |  - Evaluates urgency (ROUTINE/URGENT/EMERGENCY) |
                       |  - Determines target Department & Specialty     |
                       |  - Calls Tools / APIs to find matching doctors  |
                       +-------------------------+-----------------------+
                                                 |
                                                 v
                       +-------------------------------------------------+
                       |        Evergreen General Hospital API           |
                       |                  (Spring Boot)                  |
                       +-------------------------+-----------------------+
                                                 |
                       +-------------------------+-----------------------+
                       |                                                 |
                       v                                                 v
      +--------------------------------+                +--------------------------------+
      |      Practitioner Catalog      |                |     Appointment Scheduler      |
      | - Filter by Specialty/Dept     |                | - Availability slots calculator|
      | - Working hours & profiles     |                | - Collision validation & book  |
      +--------------------------------+                +--------------------------------+
```

## 2. Backend Scope (`api/`)

### A. Practitioner & Department Extensions
1. **Practitioner Filtering by Department & Specialty:**
   - **File:** `com.evergreen.generalhospital.controllers.PractitionerController`
   - **Enhancement:** Add query parameters:
     - `GET /api/v1/practitioners?departmentId={id}&specialty={specialty}`
   - **Repository:** Add custom query / Specifications in `PractitionerRepository`.
2. **Department Context for AI:**
   - **File:** `com.evergreen.generalhospital.models.department.Department`
   - **Enhancement:** Ensure departments include descriptions, common conditions treated, and keywords (e.g., *Cardiology: heart, chest pain, hypertension*).

---

### B. Availability & Slot Calculation
1. **Practitioner Availability Endpoint:**
   - **Endpoint:** `GET /api/v1/practitioners/{id}/availability?date=YYYY-MM-DD`
   - **Logic:**
     - Reads practitioner daily shift/working hours (e.g., `09:00 - 17:00`).
     - Breaks shift into discrete appointment slots (e.g., 30-minute intervals).
     - Queries `AppointmentRepository` for existing bookings on that date.
     - Returns available, bookable time slots:
       ```json
       {
         "practitionerId": "d2719c5d-84d1-43f6-a713-eef8a694be75",
         "date": "2026-09-01",
         "availableSlots": [
           { "start": "2026-09-01T09:00:00", "end": "2026-09-01T09:30:00" },
           { "start": "2026-09-01T10:00:00", "end": "2026-09-01T10:30:00" }
         ]
       }
       ```

---

### C. Appointment Entity & DTO Updates (Triage Data)
1. **Extend `Appointment` Entity:**
   - **File:** `com.evergreen.generalhospital.models.appointment.Appointment`
   - **Add Fields:**
     - `chiefComplaint` (String / TEXT): Patient's stated symptom/reason.
     - `triageUrgency` (Enum: `ROUTINE`, `URGENT`, `EMERGENCY`).
     - `triageNotes` (TEXT): Clinical summary generated by AI for the doctor.
2. **Update DTOs & Mappers:**
   - `AppointmentRequest`, `AppointmentResponse`, `GuestAppointmentRequest`, and `AppointmentMapper`.
3. **Patient-Specific Query:**
   - Add `GET /api/v1/appointments?patientId={id}` or `GET /api/v1/appointments/my` (using JWT context) so patients can fetch their appointments.

---

### D. Admin & Staff Onboarding
1. **Practitioner & Staff Creation Endpoint:**
   - **Endpoint:** `POST /api/v1/admin/practitioners` (Secured with `@PreAuthorize("hasRole('ADMIN')")`).
   - **Action:** Creates a `Practitioner` record, assigns `Department` and `Specialties`, and creates their corresponding `UserAccount` with `ROLE_PRACTITIONER` in a single transactional operation.
2. **Database Seeding:**
   - Provide Flyway migration or dev runner seeding realistic departments (Cardiology, Dermatology, Neurology, Orthopedics, Pediatrics, General Medicine) and practitioners.

## 3. Frontend Scope (`frontend/`)

### A. Patient Portal
1. **Appointment Hub (`/patient/appointments`):**
   - View upcoming and past appointments.
   - Status indicators (`SCHEDULED`, `COMPLETED`, `CANCELLED`).
   - Triage urgency badge and practitioner details.
2. **Booking Flow (`/patient/appointments/new`):**
   - **Tab 1: Standard Booking** (Select Department $\rightarrow$ Select Practitioner $\rightarrow$ Choose Slot $\rightarrow$ Confirm).
   - **Tab 2: AI Assisted Triage** (Conversational / Interactive intake assistant).

---

### B. AI Triage Interface Component
- **Natural Language Intake:** Patient types or dictates symptoms.
- **Real-time Assessment Card:**
  - Urgency level badge (Green: *Routine*, Amber: *Urgent*, Red: *Emergency Notice*).
  - Recommended Department & Clinical Reasoning summary.
  - Recommended Specialists with next available slots.
  - "1-Click Schedule" CTA that pre-fills and submits the booking.

---

### C. Admin & Employee Portal
1. **Practitioners Management (`/admin/practitioners`):**
   - Table of active practitioners, assigned departments, and specialties.
   - Modal/Form to onboard new staff.
2. **Department Management (`/admin/departments`):**
   - Overview and editing of department profiles and specialties.

## 4. AI Engine & LangChain Architecture

### Prompt & Tool Definition
```json
{
  "role": "system",
  "content": "You are Evergreen General Hospital's Clinical Triage Assistant. Evaluate patient complaints, assess clinical urgency, determine appropriate medical specialty, and recommend doctors."
}
```

### Structured Output Schema
```typescript
interface TriageAssessment {
  urgency: "ROUTINE" | "URGENT" | "EMERGENCY";
  urgencyRationale: string;
  recommendedDepartment: string;
  recommendedSpecialty: string;
  clinicalSummaryForDoctor: string;
  suggestedAction: string;
  emergencyWarning?: string; // e.g., "If experiencing chest pain radiating to the left arm, call 911 immediately."
}
```
